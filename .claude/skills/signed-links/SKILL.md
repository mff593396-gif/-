# Signed links for a site with no server

Any secret in client JS is public, so codes "hashed with a salt" can be generated by anyone. The fix is asymmetric: the owner signs with a **private key** that never leaves their own tool; the public site holds only the **public key** and verifies.

## Design

- **Key pair:** ECDSA P-256, `crypto.subtle.generateKey(..., true, ['sign','verify'])`. Export the private key as JWK into the owner tool's storage; publish only `{x, y}`.
- **Token:** `base64url(JSON payload) + '.' + base64url(raw r||s signature)`; the signature covers the base64url body text. Link: `https://site/#points?c=<token>` (hash, so it never reaches server logs).
- **Payload** (small, versioned): `{v:1, k:'pt'|'st', p:<phone>, o:<order code>, n:<points>, w:<0|1>, s:<stage>, t:<unix time>}`. The kind `k` is inside the signed body, so a status link cannot be replayed as a points link.
- **Public key placement:** a `<meta name="...-key" content="x.y">` tag, so setting it never changes CSP script hashes (see `csp-inline-hashes`).

## Verify on the site (order matters)

1. Extract the token from a full link or a bare paste; reject unless it matches a strict regex (`^[A-Za-z0-9_-]{16,400}\.[A-Za-z0-9_-]{60,120}$`).
2. If no public key is configured, say confirmation is not enabled yet.
3. `importKey('jwk', {kty:'EC', crv:'P-256', x, y})`, then `verify({name:'ECDSA', hash:'SHA-256'}, ...)`. **Parse JSON only after the signature passes**; fail closed on any exception.
4. Validate a strict schema (exact `v`, allowed `k`, digit-only phone, code pattern, integer ranges).
5. Bind and dedupe: require the logged-in phone to equal `p` (otherwise open login prefilled with `p` and retry after), and reject an order code already credited.
6. Remove the token from the address bar with `history.replaceState`.

## Owner tool

A single HTML page holding no secret in its code: generate key, show the public-key line, sign links, send via `wa.me`, keep a per-customer ledger, export/import a JSON backup (the backup is the only recovery path for the private key). Lock it with `default-src 'none'` and no `connect-src`, `noindex`, and request `navigator.storage.persist()`. It needs a secure context and persistent storage: host it on HTTPS at an unlinked URL rather than asking a phone user to open a local file (file previews block storage). Anyone else opening it gets an empty tool whose signatures the site rejects.

## Limits to state honestly

Balances live in the customer's browser storage, so they can edit what they see; the owner's ledger is the source of truth for redemptions. Data is per origin: a different browser or domain shows nothing.

## Test

Generate a key in the tool, set it on the page (route-replace the meta tag in Playwright), then check: valid link credits once; edited `n` is rejected; reused link is rejected; link signed by another key is rejected; wrong logged-in phone prompts login.
